## **Статус отчёт по исследовательскому проекту**

Проект: Снижение алерт-усталости врачей при проверке лекарственных взаимодействий: проектирование и оценка модуля СППВР с контекстной стратификацией рисков

Автор: Сумарокова Е. Б. (cтудентка 4 курса ИСГС, группа 640-01)

**Репозиторий:** https://github.com/ebsumarokova-svg/vkr-drug-interactions

**Доска проекта:** https://github.com/users/ebsumarokova-svg/projects/1

**План**

Общий план содержит 17 задач в нескольких логических блоках.

* Теория (4 задачи, в работе): анализ нормативных документов, литобзор по масштабу проблемы, литобзор по алерт-усталости, обзор СППВР и выявление research gap.

* Качественное исследование (3 задачи): разработка гайда интервью, проведение интервью с врачами (8–12 человек), тематический анализ и формулировка требований к дизайну.

* Разработка (3 задачи): проектирование архитектуры модуля СППВР, разработка rule-based алгоритма стратификации, создание работающего прототипа (веб-сервис + макет).

* Оценка (3 задачи): подготовка протокола юзабилити-тестирования, проведение тестирования с врачами, анализ результатов (статистика + тезисы).

* Завершение (3 задачи): формулировка дизайн-рекомендаций для МИС (ЕМИАС, РЛС, Lexema), оформление итогового отчёта/ВКР, подготовка к защите.

На начальном этапе возникли сложности с формулировкой гипотезы и выбором конкретных метрик для оценки алерт-усталости, что потребовало дополнительного времени на изучение литературы. Из-за этого теоретический блок (литобзор) идёт с небольшим отставанием от внутреннего графика.

**Риски**

Риск 1. Сложность рекрутинга врачей для интервью и юзабилити-тестирования из-за высокой загруженности медиков. 
Вероятность высокая, влияние высокое. 
Мера: начать поиск респондентов заранее через научного руководителя и профессиональные сообщества, предусмотреть стимулы для участия (если применимо).

Риск 2. Отсутствие доступа к реальным базам данных лекарственных взаимодействий (коммерческая тайна РЛС и др.) для работы алгоритма. 
Вероятность средняя, влияние высокое. 
Мера: использовать открытые датасеты (например, DrugBank) для демонстрации работы rule-based алгоритма в прототипе.

Риск 3. Технические сложности и нехватка времени на разработку полноценного веб-сервиса. 
Вероятность средняя, влияние среднее. 
Мера: сфокусироваться на качестве UX/UI макета и логике алгоритма стратификации, при нехватке времени сделать интерактивный прототип (Figma + скрипты).

Риск 4. Субъективность оценки «воспринимаемой полезности» и доверия врачей на юзабилити-тесте. 
Вероятность средняя, влияние среднее. 
Мера: использовать валидированные опросники (SUS, шкала доверия), строго следовать протоколу «мыслей вслух», привлечь не менее 10–15 респондентов для сбора статистики.

Риск 5. Смещение выборки (все врачи из одного учреждения или одного профиля). 
Вероятность средняя, влияние высокое. 
Мера: привлечь врачей разного профиля (терапевты, кардиологи, клинические фармакологи) из разных медицинских учреждений.

Риск 6. Поздний старт этапа сбора данных сжимает сроки на разработку и тестирование прототипа. 
Вероятность высокая, влияние высокое.
